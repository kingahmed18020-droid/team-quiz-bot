# 🏆 بوت مسابقات الفرق الدراسية على تليجرام

بوت مبني بـ **Python + aiogram 3 + SQLAlchemy (async)**.

## التشغيل السريع (بدون Docker)
```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # عدّل BOT_TOKEN و ADMIN_IDS
python -m quizbot
```
1. أنشئ البوت من **@BotFather** وانسخ التوكن.
2. اعرف رقمك (Telegram ID) من **@userinfobot** وضعه في `ADMIN_IDS`.

## النشر بـ Docker (موصى به): PostgreSQL + نسخ احتياطي يومي
```bash
cp .env.example .env     # عدّل BOT_TOKEN و ADMIN_IDS و POSTGRES_PASSWORD
docker compose up -d --build
docker compose logs -f bot
```
- `bot` يُعاد تشغيله تلقائياً، ويُوقف أي مسابقة جارية بنظافة عند الإغلاق.
- `backup` يأخذ نسخة يومية من PostgreSQL في `./backups` (7 أيام + 4 أسابيع) عبر صورة المجتمع `prodrigestivill/postgres-backup-local`.
- الاستعادة (اسم ملف النسخة يظهر داخل `./backups`):
  ```bash
  gunzip -c backups/last/quizbot-latest.sql.gz | docker compose exec -T db psql -U quizbot -d quizbot
  ```
- التحديث: `git pull && docker compose up -d --build` (الأعمدة الجديدة تُضاف للقاعدة تلقائياً عند التشغيل).
- بدون Docker وبقاعدة SQLite: انسخ احتياطياً بـ `sqlite3 quiz.db ".backup 'backup-$(date +%F).db'"` (يومياً عبر cron).
- عند تشغيل صورة Docker وحدها بدون `docker compose` تستخدم SQLite داخل `/data/quiz.db`، لذلك اربط مجلداً دائماً مع `/data`، مثال: `docker run -v "$PWD/data:/data" ...`.

## طريقة الاستخدام
**المشرف**
- `/admin` ← إنشاء فريق (كود من 6 خانات)، الفرق والأعضاء، بنك الأسئلة، **⚙️ إعدادات المسابقة**، بدء المسابقة، **🎛 التحكم**، الترتيب، تصفير النقاط.
- `/newteam الاسم` — إنشاء فريق سريع. `/questions` — قائمة الأسئلة وأرقامها.
- إرسال ملف `.json` أو `.html` ← يُضاف للبنك (اكتب `استبدال` في التعليق لاستبدال البنك كله).
- لربط صورة بسؤال: أرسل الصورة وفي تعليقها `صورة 12` (رقم السؤال من `/questions`).

**الطالب**: يرسل كود الفريق ← ينضم. أثناء المسابقة يضغط الحرف (أو يرسل رقماً في الأسئلة الرقمية). أوامر: `/myteam` `/leaderboard` `/leave`.

## التحكم أثناء المسابقة (🎛)
| الزر | الوظيفة |
|---|---|
| ⏸ / ▶️ | إيقاف مؤقت واستئناف — الوقت المتوقف **لا يُحتسب** على الطلاب |
| ⏭ تخطي السؤال | إنهاء السؤال الحالي دون احتسابه والانتقال للتالي |
| ⏩ السؤال التالي | يظهر في **الوضع اليدوي**: البوت ينتظرك بعد كل سؤال |
| ⏹ إيقاف نهائي | ينهي المسابقة ويرسل الترتيب الحالي |

## الإعدادات (⚙️ — تُطبَّق على المسابقة القادمة)
- **خلط ترتيب الأسئلة** (افتراضياً ❌).
- **خلط الخيارات لكل طالب** (افتراضياً ✅): كل طالب يرى ترتيباً مختلفاً، ويُحوَّل اختياره للخيار الأصلي عند الاحتساب. استثنِ الأسئلة التي فيها «كل ما سبق» بـ `"shuffle": false`.
- **التقدم يدوياً** (افتراضياً ❌).
- **بونص السرعة** (افتراضياً ✅): حتى +50% من نقاط السؤال، يتناسب عكسياً مع **متوسط زمن إجابة** أعضاء الفريق (فوري = أقصى بونص، آخر لحظة = 0).
- **الحد الأدنى للمشاركة** (افتراضياً 50%): لازم هذه النسبة من أعضاء الفريق تجاوب ليُحتسب فوزه (دائماً عضو واحد على الأقل).

## قواعد احتساب النقاط
| نوع السؤال | إجابة الفريق | الصحة |
|---|---|---|
| اختيار من متعدد `mcq` | الإجابة **الأكثر تكراراً** | تساوي الخيار الصحيح |
| رقمي `numeric` | **المتوسط الحسابي** | ضمن `± tolerance` |

نقاط السؤال = `points` (أو حسب `difficulty`: easy=5 / medium=10 / hard=15، أو الافتراضي 10) + بونص السرعة إن وُجد.
التعادل في الأصوات: يفوز الخيار الذي سبق إليه أول صوت.

## صيغ ملفات الأسئلة (أمثلة كاملة في `samples/`)
```json
{"subject":"الفيزياء","question":"...","options":["أ","ب","ج","د"],"correct_option":0,
 "difficulty":"hard","explanation":"شرح يظهر بعد السؤال","image":"https://...","shuffle":true,"time_limit":30}
{"subject":"الفيزياء","type":"numeric","question":"...","correct_value":9.8,"tolerance":0.3,"points":20}
```
| الحقل | ملاحظات |
|---|---|
| `explanation` | اختياري، يظهر مع نتيجة السؤال |
| `image` | رابط `http(s)`، أو اربط الصورة لاحقاً من تليجرام |
| `points` / `difficulty` | `difficulty`: easy/medium/hard أو سهل/متوسط/صعب |
| `shuffle` | `false` لمنع خلط خيارات هذا السؤال |

HTML: `<div class="question-item" data-subject data-correct data-time data-points|data-difficulty data-shuffle>` مع `p.question` و`ul.options > li`، و`p.explanation` و`<img src>` اختياريين. للرقمي: `data-type="numeric" data-correct-value data-tolerance`.

## ملاحظات تصميمية
- **العدّاد الحي** يعدّل رسالة كل طالب كل `COUNTDOWN_INTERVAL` ثانية. يتعطل تلقائياً فوق `COUNTDOWN_MAX_USERS` (150) طالب حتى لا نصطدم بحدود تليجرام (~30 رسالة/ثانية).
- الإجابات تُجمع في الذاكرة أثناء السؤال ثم تُحفظ دفعة واحدة؛ إعادة تشغيل البوت وسط سؤال تُنهي الجولة.
- جولة واحدة في كل مرة. ربط الصور من تليجرام يُفقد عند «استبدال» البنك.
- الترحيل التلقائي يضيف الأعمدة الجديدة فقط؛ لتغييرات أكبر في الجداول استخدم Alembic.
